# 康复需求与医学沟通（陈）

## 这条线要产出什么

1. 需求确认表：候选动作逐个由康复师判断是否可行、怎么拍、初赛建议做几个。
2. 动作与指标说明：每个确认动作的起止位、计数方法、达标角度、常见代偿、禁忌，供算法与后端据此配置规则参数（见 `docs/03-接口契约.md` C 节）。
3. 康复师反馈记录：每次访谈或测试后的问题清单、原话要点、规则修改建议、待办。

## 产出顺序

1. **先定场景与动作**：用 `需求确认表.md` 让康复师在候选动作里勾选，明确初赛只做哪一个（或哪几个）动作、摄像头怎么摆。
2. **再定指标与阈值**：动作定下来后，用 `动作与指标说明-模板.md` 逐个动作写清楚计数方法、达标角度、代偿判断、阈值来源，交给后端与视觉算法（常）落进 `rule_versions` 表。
3. **再组织测试与反馈**：拿到规则草稿后，安排至少两名具备资质的康复专业人员独立评分测试，把过程和结论记进 `康复师反馈记录.md`。

## 访谈与记录的红线

- 不记录患者可识别信息：不写真实姓名、身份证号、具体住址、可识别的病历号；用编号或职称代替。
- 只记录训练与规则相关的信息，不记录与目标无关的健康或个人信息。
- 涉及真实患者的测试须在指导单位审批、知情同意和风险预案下开展。
- 规则每次修改都要留版本、依据和审核人，对应 `docs/02-数据字典.md` 里的 `rule_versions` 表设计。
