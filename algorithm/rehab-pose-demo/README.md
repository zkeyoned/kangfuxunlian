# 康复视觉演示 v0.7（常的本地 VS Code 项目）

## v0.7 动作1量化标准

动作1已按团队提供的《坐姿伸膝动作量化标准 v0.1》更新。默认目标膝夹角170°、连续保持5秒；起始姿势稳定2秒后，以个人起始膝角为基线。膝角相对基线增加10°并持续0.2秒才启动；达到170°持续0.2秒才确认进入目标；目标带采用5°滞回；峰值下降5°持续0.2秒才确认回落；回到起始角±10°并稳定0.5秒才闭合一个完整周期。

每次动作新增输出 `knee_start_deg`、`knee_peak_deg`、`knee_excursion_deg`、`time_to_target_s`、`target_hold_s`、`return_s`、`cycle_duration_s`、`target_reached` 和 `target_completed`。完整周期数与目标完成数分开，`summary.json` 增加 `target_completed_reps` 和 `action_standard_version`。

仓库接口仍使用 `docs/03-接口契约.md` A节规定的扁平rep结构。`rehab_pose/contract.py` 把内部详细结果转换为 `rep_index / peak_angle / duration_ms / valid / flags`，并写入 `summary.json` 的 `contract_reps`。因此本次没有修改公共接口契约；前端和后端应读取 `contract_reps`，详细研究字段继续保留在 `repetitions`。

动作1前倾/后仰超过相对基线15°、大腿移动超过10°均需持续0.5秒才提示；同类提示冷却5秒。瞬时 `knee_velocity_deg_s` 继续输出，但快慢结论改为阶段用时：到达目标或返回少于1秒才判定过快。MediaPipe暂用0.70可见性阈值；真实录像证明RTMPose的模型分数不能直接套0.70，仍用0.30并在结果配置快照中记录。

真实旧录像回归：2644帧中1930帧可靠，按新规则识别5个完整周期，其中0次达到“170°并保持5秒”；旧版同一录像曾计8次，差异来自新的返回带、目标确认和保持规则。该结果用于工程回归，不代表临床准确率。81项自动测试通过。简洁动作指导见 `ACTION1_QUICK_GUIDE.md`。

## v0.6 动作2 / 6 / 8

三种动作现接入组数、自由输入次数、组间休息、暂停、报告。保持设置：动作1仍为2～3秒；动作2为5秒；动作6/8为0（不强制顶点保持）。选择动作后自动切换保持设置。结束时未完成计划记为ended_incomplete。报告含逐项指标、实际提醒和明确不支持的项目。

这些是用户提供要领的实验性实现，不是统一临床标准，未经过康复师验证。AAOS直腿抬高资料包含不同支撑姿势和抬高方式，不能将用户给的30～45度视为所有患者处方；NHS坐立指导明确包括起身前倾，因此本程序不对坐立起身阶段套用15度前倾错误规则。

### 新增规则

配置位于config/knee_extension.json的exercise_rules。动作2：训练腿膝夹角低于170度视为超过10度屈膝容差（技术容差，不是肌肉判断）；抬升用大腿相对初始方向变化，目标30～45度，保持5秒，超过45度的样本不累计保持。腿弯会中断计数，同时提供提示；大腿角速度默认90度/秒、躯干变化15度均为待验证的技术阈值。

动作6：超过90度膝屈曲提示过深，躯干相对画面竖直前倾超过15度提示，膝角速度默认180度/秒。最低下蹲目标仍来自exercise_profiles中的相对角度信号（默认30度）；可由康复师调整。不判断内扣、脚跟离地、双腿受力或实际扶握。

动作8：膝夹角目标165度；到达站立阶段才检查躯干倾斜15度、肩髋膝代理髋屈曲20度；起身过程允许正常前倾。检查完整往返、返回用时和膝角速度；不能据此判断是否借手、落座冲击力、真正椅面接触或负重对称。

取景仍需固定侧面、训练侧关节完整可见。动作2的抬腿角是相对初始大腿方向的二维值，不是校准过的三维髋角；躯干变化不等于腰椎/骨盆旋转。微蹲与坐立只分析选定侧，不能宣称双侧全面评估。

验证：79项测试通过，包括动作1旧记录回归；SLR5秒保持、过高不累计保持、屈膝提示、大腿角速度；微蹲过深前倾；坐立正常前倾不报错与站立阶段检查；三动作报告及未完成状态。三个模式均通过短视频启动/输出冒烟检查（输入不是对应动作，不能作为识别验证）。尚无2/6/8真人动作标注对照验证，模型权重未改变。

## v0.5 单侧训练计划

每组次数现改为手动输入，可填1～100的整数（软件输入边界，非训练建议），默认10；开始前校验空值、文字、小数和越界输入。训练进行中禁用次数输入，避免页面目标与当前计划不一致。此项替代下文原先10～15的下拉选择说明。

启动页动作1默认3组×10次、保持2秒；可选3～5组、每组10～15次、保持2/2.5/3秒。组间休息30秒。以上为用户指定的演示设置，未经临床确认；只控制本次单侧训练，不是每日累计量或处方。CLI通过--sets启用计划，--reps-per-set和--hold-seconds设置次数和保持；不传--sets保持原离线分析行为。

次数按完整动作周期累计，包含未达到保持/速度要求的动作；质量另行报告，不强迫补做至全部合格。每组结束自动休息，休息和手动暂停期间不计数、不累计保持；下一组或手动恢复后重新标定。暂停按钮或视频窗口P切换暂停/恢复；最后一组完成自动结束保存。训练过程中调整启动页选项不会修改正在进行的计划。计数后换训练侧需结束本次计划重新开始。

summary.json与assessment.json增加training_session：计划、当前组、组内次数、剩余休息、暂停/恢复事件。frames.jsonl增加training_progress；报告解释次数不等于达标次数。未完成就关闭窗口不会标为计划完成。

勾选保存录像后同时输出source.mp4（叠加前画面）与annotated.mp4。source是编码后的视频而非无损传感器数据；若输入本来带标注，source也仍有原来的标注。默认不保存视频，磁盘占用约增加一份录像。用于后续固定回归，不修改模型权重。

验证：71项测试通过，包括已知坐标记录恢复3次动作和前倾/速度提醒、休息30秒边界、暂停冻结休息倒计时、重复计数保护等。对221040的annotated.mp4重新推理仍未标定、计数0次；这是已标注压缩输入的测试，不能宣称视觉稳定性改善或临床测量准确。原始视频回归和真人连续多组试验仍待进行。

## v0.4.2 先确认训练腿

检测到疑似串侧、重新选择训练者或画面尺寸变化时重新确认腿。未检测到的缓慢串侧仍可能漏掉，当前不是可靠的腿身份锁定。无预览的离线分析继续使用指定侧，结果leg_confirmation.required=false，不能视为经过人工确认。

动作1标定后，前后倾提醒也在rest阶段生效；速度超限持续时间由0.3秒改为0.08秒，姿态偏移仍需0.3秒；均保留3秒冷却。慢本身不自动判错，未设置临床速度上限。大腿明显接近竖直（画面角度绝对值超过50度）时中断当前尝试并重新标定，作为离开坐姿的实验性保护，不能识别全部起身情况。

61项测试通过，覆盖静止阶段前后倾提醒、短促快速动作、慢动作不误报、未标定不判定和选腿确认。旧213007记录回放仍没有有效标定（最高进度68.75%），无法通过更新代码补出可靠动作结论。没有宣称新流程已通过真人实拍验证。

## 画面清晰度设置

### 动作1新增结束报告

训练结束后，在同一结果目录生成assessment.json（前端/程序可读）和assessment.md（中文报告）。包含每次已记录尝试的观测膝角最大值、最小值、变化幅度、有效观测帧比例、预测帧数，以及幅度/保持/返回用时的逐项判断。中断、预测衔接或采样不连续的尝试保守标记为无法判断。质量比例不是测量准确率；角度变化幅度只覆盖计数器记录的动作区间，不是临床活动范围。报告不评估肌肉发力，也不代表整体动作合格。

已有记录可运行 `.\.venv\Scripts\python.exe -m rehab_pose.assessment results/对应目录` 补生成报告。原frames.jsonl和summary.json保持原样。该功能仅为动作1的离线报告，实时前端接口尚未接入。

启动窗口可选择480p、720p（默认）或1080p。程序请求该分辨率，但设备可能不支持；启动日志和summary.json的capture字段会记录实际收到的画面尺寸，请以实际值为准。没有通过开启真实摄像头验证本机支持哪些分辨率。

保存录像时已提高编码目标码率，文件可能变大。此设置减少录像压缩造成的细节损失，不会恢复失焦、运动模糊或原视频丢失的细节；导入视频不会因此变成高清。识别发生在录像编码之前，录像码率不改变该次识别结果。

试拍时擦净镜头、面向均匀光源、固定相机，让训练侧髋膝踝在画面内占足够大小。可与Windows相机应用在相同光照和取景下对照，再判断是否需要换摄像头。

本轮只修改视觉测量程序，没有连接网页或数据库，没有修改团队仓库。模型没有重新训练；锁定模式新增官方YOLOX-m检测器，其余优化集中在跟踪、参考姿态、指标和动作规则。

## 第一次试拍：仍建议动作1

1. 选择动作1坐姿伸膝、训练侧，以及“脚伸出方向”（指原始画面左/右，不是身体左右侧；视频不镜像）。
2. 单人近景可继续选“固定单人画面”。它不检测人数，没有防旁人功能。
3. 固定相机侧面拍摄，髋、膝、踝全程在画面内并留边缘余量；需要躯干指标时肩也要可见。
4. 坐好、腿放下，稳定保持约2秒，等画面显示Reference: ready后再做动作。方向选错、起始姿态不符或关键点一直抖动时不会完成标定。请查看进度和提示，不能直接把0次解释成模型完全未识别人。
5. 移动相机或改变座位后，在视频窗口按B重新标定。Q/Esc退出，启动窗口“停止”也可以结束。

标定是图像姿态参考，不证明起始动作正确，不是临床量角器标定。相机需保持固定、尽量从侧面拍摄。

## 锁定训练者（实验）

选择RTMPose和“锁定训练者（需确认）”：画面中出现人体框后点击目标，再按C确认。仅检测到一个人时直接按C。按R取消并重选。

使用人框连续性和躯干区域颜色直方图核对目标。远处、不重叠的旁人可被忽略；目标漏检、两个框重叠或匹配不明确时，立即暂停并要求再次确认，不自动换到新的人。重新确认会重新标定，动作结果保存target_generation用于区分确认段。

这不是人脸识别或可靠身份认证。相似衣着、检测器漏人、极快替换可能仍误配；不能承诺绝不串人。锁定模式使用YOLOX-m，对截断近景仍可能漏检，导致锁定失效；普通检测模式保留YOLOX-tiny。锁定模式在本机CPU的抽帧检测约0.17秒/帧，比近景模式慢，低帧率也会削弱短暂遮挡衔接效果。没有人体框时先扩大取景，或回到固定单人模式仅测试角度。后者不能宣称防干扰。

## 新指标与提示

逐帧measurement_metrics提供：

| 字段 | 单位与定义 |
| --- | --- |
| knee_included_deg | 度；同侧髋—膝—踝夹角，伸直趋近180 |
| knee_flexion_deg | 度；180减去膝夹角，二维代理值 |
| trunk_signed_deg | 度；肩—髋方向相对画面竖直方向，按用户选择的朝向定义前倾为正、后仰为负 |
| trunk_delta_deg | 度；相对初始躯干方向的变化；无可靠肩点时为null |
| thigh_elevation_deg | 度；髋到膝方向相对画面朝前水平线，向上为正 |
| thigh_delta_deg | 度；相对初始大腿方向的变化 |
| hip_flexion_proxy_deg | 度；180减去肩—髋—膝夹角，躯干参考的二维代理值，不能代表真实骨盆姿态 |
| knee_velocity_deg_s | 度/秒；最近0.2秒观测膝角按实际时间做直线拟合；正值为伸膝，负值为屈膝。不是脚移动的米/秒，也不是肌肉力量 |

标定取连续稳定窗口的中位数；关键点中断会重新等待稳定，丢失超过2秒会使参考失效。缺少肩部时动作1仍可标定膝角和大腿方向，但躯干相对指标为null。

动作1训练中提供躯干前/后偏移与大腿变化提示；异常持续0.5秒才触发，同类提示间隔5秒。完成动作后比较幅度、连续保持、到达目标用时和返回用时。事件含中文message和英文code；视频窗口显示code，JSON保留完整中文。

当前动作1测试值包括躯干相对变化15度、大腿相对变化10度、目标膝夹角170度和连续保持5秒。`knee_velocity_deg_s`仅作为观测数据；动作快慢按阶段实际用时判断。这些规则集中在config/knee_extension.json中，仍需康复师审核和真人测量验证。

## 动作2、6、8：仅实验规则

复用姿态模型，各有起始条件与阶段信号，尚无相应实拍验证。

| 动作 | 起始标定 | 计数依据及限制 |
| --- | --- | --- |
| 1 坐姿伸膝 | 坐姿屈膝，大腿接近水平 | 膝夹角增加—保持—返回；已用旧录像调试，尚无人工角度真值 |

沿用v0.3最多0.25秒的单点短暂预测。橙色虚线仅用于显示，不计算角度或保持时长。恢复后连续两帧核对，衔接动作标记needs_review；相关阶段用时为null。多人、无人、出画和明显异常不补猜。

One Euro速度自适应参数beta从0.04调至8（坐标单位为归一化坐标），用于减小运动时滞后；合成信号测试通过，但不代表解剖点定位精度提高。仍然可能抖动、漏计或稳定地定位错误。

## 输出

每次运行创建独立results目录，旧数据不覆盖。当前动作1输出schema_version为1.4，algorithm_version为0.7.0。

- frames.jsonl：原始与过滤后的关键点、预测显示、膝角、measurement_metrics、calibration、subject、feedback_events和动作阶段。
- summary.json：动作结果、配置快照、模型哈希、标定参考、提示事件和实验标记。
- annotated.mp4：仅选择保存视频时生成，不含音轨。使用输入采集时间戳。未保存原始视频。

观测、预测和不可测分开。null表示未知，不能当成0或自动判定不合格。坐标仍为原画面像素，角度都是二维估计值，模型置信分数不是准确率。
