# algorithm（后端负责人：后端（常），含视觉算法）

## 职责边界

这个模块只吃摄像头关键点，只吐帧级指标和计次结果，不碰摄像头采集、不碰网络请求、不直接写数据库。它是前端（景）和后端（常）之间的纯计算层：前端调用它拿到每一帧的角度和状态，攒成一组结果后再按 `docs/03-接口契约.md` B 节的格式上报给后端接口。

具体识别哪些动作、评价标准怎么定，待康复师确认，本目录内的动作候选方案（膝关节屈伸、直腿抬高、下蹲、坐站转移等）都可能调整，不是最终定案。

## 输入输出契约

完整定义见 `docs/03-接口契约.md` A 节，这里复制一份字段表方便对照，改动以 docs/03 为准。

### 每帧输出（`computeMetrics(landmarks, exercise, side, minVisibility) -> {value, aux, visible, confidence}`）

```json
{
  "value": 96.4,
  "aux": {
    "kneeAngle": 96.4,
    "hipAngle": 148.2,
    "trunkLean": 7.5
  },
  "visible": true,
  "confidence": 0.91
}
```

- `value`：本动作的主指标（角度）。不同动作对应不同关节角，具体取哪个角待康复师确认后在规则参数里指定。
- `aux`：辅助指标，供代偿判断用。
- `visible`：相关关键点的可见度都达到规则参数里的 `min_visibility` 才为 `true`，为 `false` 时不计数、提示用户调整姿势。
- `confidence`：可选，整帧综合置信度，0 到 1。

### 计数状态机

```
rest --(越过 start_threshold)--> moving --(峰值稳定 hold_ms)--> peak --(回落到 start_threshold-3°)--> rest（记一次）
```

每记一次动作，产出一条 rep：

```json
{ "rep_index": 3, "peak_angle": 95.2, "duration_ms": 3800, "valid": true, "flags": [] }
```

`flags` 只能用契约里约定的几个枚举值（幅度不够、过快、躯干前倾、膝未伸直等），前端靠它显示实时提示，后端靠它扣分和记代偿次数。`valid` 只看是否达到有效幅度且没有过快标记，代偿类标记不影响 `valid`，但计入 `compensation_count`。

## 建议技术路线

- 关键点来源先对比 **MediaPipe Pose** 和 **MoveNet**，看手机浏览器端的帧率和精度取舍，实测数据记进 `experiments/`。
- 角度计算走纯几何（三点夹角），不需要额外训练模型。
- 计次用上面的状态机，阈值和平滑窗口都放进规则参数（`rule_versions.params`），不写死在代码里，方便后续按病种/病人调整。
- 代偿判断（躯干前倾、膝未伸直等）先用简单阈值规则，积累数据后再考虑更复杂的模型。

## experiments/ 怎么用

放算法对比实验的记录和结论（比如两种关键点模型的帧率、精度对比表），只放文字总结、表格、截图，不放原始视频和关键点导出。目录当前只有一个 `.gitkeep` 占位。

## 不提交什么

- 不提交任何训练/测试用的视频文件（`.mp4` `.mov` `.avi`）。
- 不提交原始关键点导出（逐帧坐标的 `.json.gz`、`.npy` 等），这些属于运行数据，只在本地或 `data/` 目录保留，已被 `.gitignore` 排除。
- 需要留存分析结论时，把结论写成 Markdown 或表格提交，不要把原始数据一起打包进仓库。
