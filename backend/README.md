# backend（后端负责人：后端（常））

## 这是什么

一份可以直接跑起来的参考实现，FastAPI + SQLite，纯标准库加少量依赖。用来把接口契约先跑通，让前端、算法、数据库三方能对着一个真实服务联调，不是最终交付形态，后端负责人可以在此基础上重写或替换任意一部分。

## 怎么起

```bash
pip3 install -r requirements.txt
python3 backend/main.py 8801
```

默认监听 `0.0.0.0:8801`，方便同一 Wi-Fi 下用手机测试。服务器上部署时设置环境变量 `REHAB_BIND=127.0.0.1`，只经 `deploy/` 里配的反向代理对外，见 `docs/04-部署方案.md`。

也可以直接用仓库根目录的 `./start.sh`。

## 接口一览

跑起来之后访问 `http://127.0.0.1:8801/docs`，FastAPI 自动生成的交互式文档，所有路径、请求体、返回体都在那里。字段含义与三方约定见 `docs/03-接口契约.md`。

健康检查：`GET /healthz`。

## 文件说明

- `main.py`：路由、鉴权、机构隔离、业务逻辑。
- `db.py`：数据库连接、建表、灌演示数据、密码哈希、令牌签发。
- `scoring.py`：评分缺省算法，前端没传 `quality_score` 时用这份公式补一个，并保留每个维度的拆分（`score_breakdown`），保证报告能解释分数怎么来的。真正的评分公式归算法（常）负责调优，这里只是保底实现。

## 后端负责人要接手重写的部分

- `scoring.py` 里的默认权重和归一化方式，等算法侧有更好的评分模型后替换。
- 机构管理、康复师排班等运营功能目前只有最小实现，按实际需求扩展。
- 告警规则（`alerts` 表怎么触发）目前有 pain_high（疼痛过高）、compensation_high（代偿过多）、low_capture（拍摄质量低）、angle_drop（峰值角度退步）、inactive_3d（连续 3 天未训练）五条，阈值见 docs/02-数据字典.md，需要和医学（陈）确认后再调整。
- 前端静态托管目前是最简单的 `StaticFiles` 挂载，`frontend/` 里没有页面文件时根路径会退化成一段 JSON，等前端页面就绪后按需调整。

## 不该随意动的部分

以下几处涉及数据安全和一致性，改之前务必想清楚影响范围，最好先在 `docs/decisions/` 记一条：

- **鉴权**：`current_user()` 的令牌校验逻辑，以及密码哈希用的 `pbkdf2_sha256` 参数（`db.py` 的 `hash_password`/`verify_password`）。
- **机构隔离**：`patient_in_scope()`，康复师只能看本机构患者、患者只能看自己，这是多机构演示部署的安全边界。
- **审计日志**：`audit_logs` 的写入点，删除或跳过会导致操作不可追溯。
- **规则激活的双人审核闸门（409）**：`reviewer` 为空的规则版本不许激活，防止只有一人拍板就上线新阈值。

## 测试

```bash
python3 backend/main.py 8801 &
python3 tests/test_api.py
```

冒烟测试跑一遍完整闭环（登录、建计划、上传训练组、生成报告），失败会直接抛出并带上请求方法、路径和响应内容，方便定位。合并前必须全过。

## 训练简报同步

网页训练结束自动调用 /api/v1/training-reports 保存视觉展示快照，患者反馈和已关联康复师报告页共享读取。增量迁移002_training_reports.sql与接口契约F节待前端/数据库审核。结果不转换成旧种子动作代号，不调用旧质量评分，不存视频或原始关键点；sessions/items的正式算法映射仍待对齐。

使用 backend/test_training_reports.py 在临时库验证去重、零次与缺失指标保留、双方权限、解绑及后续关联、已读。外置前端需同时更新app.js/index.html，主按钮为查看动作反馈，失败可重试，下载只是备份。参见本地前端LOCAL_INTEGRATION.md。
