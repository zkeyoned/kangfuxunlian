# 决策记录怎么写

`docs/decisions/` 存放本仓库的重大决定，每条一个独立文件，文件名格式 `NNNN-简短标题.md`（四位编号从 0001 起递增）。

## 什么值得记一条

- 仓库结构、目录归属、分工边界的变化。
- `docs/03-接口契约.md` 里字段的新增、删除或语义变化（三方共有文档，改动必须记录）。
- 部署方式、技术选型（如数据库迁移）的变化。
- 任何会影响多个角色协作方式的决定。

日常代码改动、文案微调不需要记。

## 模板

```markdown
# NNNN · 标题

- 日期：YYYY-MM-DD
- 背景：为什么要做这个决定，之前是什么状态。
- 决定：具体决定了什么。
- 影响谁：哪些目录/角色/文档需要跟着变。
- 谁签：参与决定或知会到的角色（写「角色（字）」，不写真实姓名）。
```

## 流程

1. 谁发起改动，谁先写决策记录草稿。
2. 涉及的角色都过目后，把决策记录和实际改动一起提交。
3. 决策记录只增不改：确需推翻旧决定，另开一条新记录并引用旧编号，不要直接编辑历史记录。
