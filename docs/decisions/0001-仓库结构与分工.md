# 0001 · 仓库结构与分工

- 日期：2026-09-16
- 背景：此前只有一份单人视角的技术骨架，目录按临时编号组织，边界不清。团队实际分工已确定为五个角色，需要一个所有人共同维护、边界清楚的正式仓库。
- 决定：
  1. 建立本仓库 `kangfuxunlian` 作为正式协作仓库，取代原有单人视角骨架。
  2. 目录与角色一一对应：`materials/` 计划书与比赛材料（胡）、`frontend/` 前端页面（景）、`database/` 数据库（得）、`backend/` 与 `algorithm/` 后端与视觉算法（常）、`medical/` 康复需求与医学沟通（陈）、`deploy/` 部署与上线（暂由数据库负责人（得）兼管）。
  3. `docs/` 为公共目录，其中 `docs/03-接口契约.md` 由前端（景）、后端与视觉算法（常）、数据库（得）三方共有，任何一方改动前须知会其余两方，并在本目录补一条决策记录。
  4. `frontend/` 目录只保留 `AGENTS.md` 与 `README.md`，可运行的前端页面由前端（景）从零重做，不直接沿用旧参考实现；旧参考实现仍可在本地骨架项目里找数据库负责人（得）索取，仅作参考，不进本仓库。
  5. 部署（`deploy/`）现阶段暂由数据库负责人（得）兼管，待人手或分工调整时另行决定。
- 影响谁：全部五个角色；尤其前端（景）需要基于契约从零搭建页面，数据库（得）需要把原技术骨架的 schema 与种子数据挪到 `database/` 并调整后端里的路径引用。
- 谁签：计划书与比赛材料（胡）、前端（景）、数据库（得）、后端与视觉算法（常）、康复需求与医学沟通（陈）。
