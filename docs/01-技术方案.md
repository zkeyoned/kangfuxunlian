# 01 · 技术方案：服务端 / 数据 / 权限 / 机构端 / 部署

> 对应商业计划书「技术路线」「团队分工」「隐私安全」相关章节。
> 状态：v0.1 骨架已跑通，接口测试全过。

## 1. 各角色负责什么、不负责什么

| 负责 | 不负责（归谁） |
|---|---|
| API（患者端 + 康复师端全部接口）（后端与视觉算法（常）） | 数据库设计与迁移（数据库（得）） |
| 摄像头、关键点、角度、状态机（后端与视觉算法（常）） | 患者端界面与交互（前端（景）） |
| 登录、角色、机构隔离、审计（后端与视觉算法（常）） | 动作规则的内容和阈值（康复需求与医学沟通（陈）+ 后端与视觉算法（常）共定） |
| 评分的缺省实现与校验（后端与视觉算法（常）） | 评分公式的最终定义（后端与视觉算法（常）与康复需求与医学沟通（陈）共定） |
| 康复师工作台、规则库页面（机构端）（前端（景）） | 访谈、采集、测试集（康复需求与医学沟通（陈）） |
| 数据库设计与迁移、schema、数据字典、seed（数据库（得）） | 计划书、路演（计划书与比赛材料（胡）） |
| 部署（云服务器 / HTTPS / 进程守护 / 日志）（数据库（得）暂管） | — |

一句话：算法管"量得准不准"，前端管"看得清不清"，后端管"接口通得顺不顺、跑得对不对"，数据库管"存得住、管得了、上得线"。

## 2. 架构

```
   患者手机/电脑浏览器                              康复师电脑/手机
   ┌────────────────────┐                        ┌────────────────────┐
   │ 训练页面             │                        │ 康复师工作台         │
   │  摄像头→关键点→角度  │  只上传指标，不传视频     │ 规则库页面           │
   │  →状态机→评分（端侧）│ ──────────────┐        │  列表/趋势/计划/提醒 │
   └────────────────────┘               │        └─────────┬──────────┘
                                        ▼                  │
                     HTTPS（自动证书）◀──────────────────────┘
                                        │
                          ┌─────────────┴──────────────┐
                          │ FastAPI  backend/main.py    │
                          │  · 鉴权/角色/机构隔离        │
                          │  · 规则版本分发              │
                          │  · 提醒生成 · 审计 · 导出     │
                          └─────────────┬──────────────┘
                                        │
                          ┌─────────────┴──────────────┐
                          │ SQLite（WAL）→ PostgreSQL   │
                          │ data/rehabtrack.sqlite3     │
                          │ data/logs/app.log（滚动）    │
                          └────────────────────────────┘
```

**端侧优先**：姿态识别和计数在浏览器里跑（MediaPipe Pose WASM），服务器只收结构化结果。好处三条：隐私（视频不出手机）、成本（服务器不跑模型，2 核够用）、延迟（实时反馈不经网络）。

## 3. 请求流（一次训练）

```
1  POST /auth/login                       → token（72h）
2  GET  /me/plan/today                    → 计划 + 每项的规则参数（阈值下发）
3  POST /sessions                         → session_id，服务端快照当时所有规则版本
4  POST /sessions/{id}/items  × N         → 每组一条（契约见 docs/03）；缺 quality_score 时服务端补算
5  POST /sessions/{id}/finish             → 跑提醒规则（疼痛/代偿/退步/拍摄质量）→ alerts
6  GET  /sessions/{id}  ·  GET /me/trend  → 报告与趋势
```

康复师：`GET /patients`（含 7 天完成率、质量、未处理提醒、3 天未训练检查）→ `GET /patients/{id}`（档案 + 计划 + 记录 + 提醒）→ `POST /patients/{id}/plans` / `GET .../export.csv` / `POST /rules`。

完整接口列表见本地部署后的 `/docs` 页面。

## 4. 权限模型

| 角色 | 能看 | 能写 |
|---|---|---|
| patient | 自己的计划、训练、趋势 | 自己的训练记录 |
| therapist | 本机构所有患者 | 患者档案、计划、提醒处理、规则版本、导出 |
| admin | 同 therapist + 审计日志 | 同 therapist |

- 机构隔离在每个读接口里用 `patient_in_scope()` 强制，不靠前端。
- 令牌存表，退出即删，过期自动失效；密码 PBKDF2-SHA256 20 万轮。
- 敏感动作全部写 `audit_logs`（登录、看档案、开计划、导出、改规则、处理提醒）。

## 5. 规则版本化（评审最爱问的点）

阈值不在代码里。`rule_versions` 一行一版：`params_json` + `rationale`（来源）+ `author` + `reviewer`。

- 同一动作只有一个 `is_active`。
- **没有 reviewer 的版本 API 拒绝激活**（409）。把"双人审核"做成机器强制。
- 每次训练开始时把当时的激活版本快照进 `sessions.rule_versions_json`，事后复盘知道那天用的是哪版规则。

## 6. 隐私与安全（已做进代码的打勾）

- ✓ 不收视频、不收关键点；`angle_trace` 只是角度数字序列。
- ✓ 患者/康复师/管理员三级；机构逻辑隔离；审计日志。
- ✓ 传输加密（自动 HTTPS）；凭证哈希存储；进程守护最小权限。
- ✓ 知情同意版本化（`consents`）。
- ○ 用户删除权（`DELETE /patients/{id}` 级联，下一版）。
- ○ 备份：每日 `sqlite3 .backup` 到对象存储（下一版，脚本约 5 行）。
- ○ 低置信度不给强提示：后端已把 `low_confidence` 组排除出趋势和 angle_drop 提醒；前端提示文案归前端（景）。

## 7. 日志与可观测

- `data/logs/app.log`：每个 API 请求一行（方法、路径、状态码、耗时、IP），5MB 滚动 ×5。
- `GET /healthz`：进程活、库能读。
- 部署后加：反向代理访问日志、系统日志；错误告警走消息渠道 webhook（下一版）。

## 8. 扩展路径（别现在做）

| 触发条件 | 做什么 |
|---|---|
| 多机构 / 并发写入明显 | SQLite 迁移 PostgreSQL（只改 `db.connect()` + 少数 SQL 方言） |
| 前端想独立部署 | 前端静态托管到 CDN，后端只留 API，CORS 已开 |
| 要看原始关键点做算法迭代 | 单独加 `keypoint_samples` 表 + 独立授权，默认关闭 |
| 机构要接医院信息系统 | 加导出接口（下一年的事） |

## 9. 已知风险

1. **CDN 依赖**：姿态识别模型与图表库走公共 CDN，校园网偶发慢。演示前把模型文件本地托管。
2. **移动端 GPU 加速**在部分安卓机不可用，需回退 CPU，由后端与视觉算法（常）、前端（景）联调解决。
3. **提醒阈值**（疼痛≥6、代偿≥30%、退步≥8°、3 天未练）全是 v0.1 假设，等康复需求与医学沟通（陈）审核。
4. **单机 SQLite** 不适合两台服务器同时写；试点期一台够。

## 10. 技术路线小结（对应商业计划书技术路线章）

成熟姿态识别 + 可解释运动学 + 状态机，先做可靠 MVP，再逐步引入学习模型。原则：端侧优先推理、最小化数据采集、参数可配置、全链路留痕。

技术护城河不等于自研基础模型。真正可积累的资产是经过专家审核的动作规则库、带版本的数据集、家庭场景失败案例、个体化标定方法与机构工作流。
